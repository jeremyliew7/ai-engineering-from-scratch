# 课程仓库维护

将上游更新与个人学习产物一起维护。译文只是关联产物的一类，不能把任务缩减为拉取代码或只检查翻译目录。

## 调用与范围

在当前 AI Engineering from Scratch 仓库执行。先读取 `AGENTS.md`、`AGENTS.override.md`，按当前约定确定分支，不硬编码用户名、磁盘路径、提交号或课程总数。

```text
使用 course-update，更新课程仓库，同步受影响的本地产物，说明变化并完成本地提交。
使用 course-update，只检查更新及对我已有文件的影响，先不修改。
使用 course-update，维护当前已合入的更新，不再拉取远程。
```

默认执行完整维护：远程同步、关联文件更新、技能说明与获选技能注册、README 维护、验证、本轮相关变更的本地提交。用户指定只检查、暂不提交等范围时按当次要求执行。只检查模式不改工作区、索引或分支；如需刷新远程引用，先说明会 fetch。

新增技能先列清单等用户选择；当次已明确授权全部或委托判断时直接执行。此前选择一批技能不代表以后全部自动安装。推送仍需明确授权。

## 1. 同步前记录与远程合并

- 记录 Git 根、分支、HEAD、远程地址、暂存区、工作区及未跟踪文件；检查操作标记和锁，记录已有个人文件哈希与暂存状态。
- 根据本地规则、索引、个人提交相对共同祖先的差异识别个人产物，不仅看 Git 作者，也不把所有上游文件判作用户文件。候选范围包含学习记录、`learning-artifacts/`、练习脚本、笔记、个人配置、技能及其说明。
- 通常 `origin` 是个人仓库，`upstream` 是原作者；以当前地址和用户指定来源为准，不顺带同步其他 remote 或改持久配置。每条 fetch 检查退出码，使用刷新后的引用比较领先、落后及共同祖先。
- 有未提交改动时，可先 fetch、分析依赖和路径重叠。本轮已授权且归属清楚的改动按范围保存；无关改动不得擅自提交、stash、reset 或 clean。实际存在覆盖风险时，给出具体重叠与保存方案再解决，继续不依赖它的检查。
- 个人远程可快进则快进，上游与个人历史分叉则按约定合并并保留个人提交，不重置或改写历史。禁用自动 stash；操作前复核分支、HEAD、文件快照和锁，发现并发漂移先停止相关写入。
- 可用 `git merge-tree --write-tree` 预检；其退出码 1 表示冲突，不表示已进入实际合并。`site/data.js` 等生成文件冲突按当前 AGENTS 重建。构建的附带变更只在确认由本轮产生后按需处理，保留已有用户改动。
- 依据两侧语义解决普通冲突；无法确定个人定制意图时具体询问。保留同步前后引用，用实际 diff 总结更新，区分 CI 构建提交与功能变化。

远程无新提交，也需检查先前未同步的本地产物版本漂移。不能仅因 HEAD 已含上游就断言维护完成。

## 2. 追踪并同步关联的本地产物

从实际上游变更路径出发，追踪直接及间接依赖。不要只用一个固定目录名单，也不能只靠同名文件判断关联。

| 上游变化 | 本地检查入口 |
|---|---|
| 课程正文、练习、参考代码、测验 | 已有译文、练习副本、课程笔记、源版本记录 |
| 路径、命令、函数签名、依赖、配置示例 | 本地导入、调用脚本、配置、文档链接和环境说明 |
| 项目、专题路线或前置条件 | 本地路线引用、索引、相关说明 |
| Skill、参考资料、模板 | 已注册入口、个人适配、技能 README |

搜索源路径、相对路径、文档链接、命令和符号引用，并阅读上下文作语义判断。例如辅助模块变化可能影响练习，虽然该课正文未变；没有文字链接也不能直接判为无影响。

为每个候选产物记录“需更新／核对无影响／需重跑或用户决定”及依据。随后：

- 修正相关路径、接口、配置、说明与索引，保留用户正文、学习意图和已有校注。兼容性修复不应代写练习答案。
- 旧实验数字和结果保留原版本，不无实测地替换。需要重新验证时标明待验证；不能因上游新增题目而改写完成状态、成绩或断点。
- 学习记录仅在确有受影响内容且符合当前记录约定时更新；不顺带写仓库外的 BOOT、MEMORY、SESSION 等状态文件。
- 需要替换练习实现、迁移环境、安装依赖或重跑有成本的训练时，先完成已授权的独立维护，再说明具体影响和必要操作。未经相应授权不执行这些操作。

### 已有译文的维护

1. 读取 `learning-artifacts/course-translations/translation-manifest.json`，完整读取受影响的当前英文源文，并从每课记录的提交还原旧源，识别全部变化。
2. 在原章节位置同步增删改正文、表格、练习和提示；代码按源文原样保留并配中文说明。保留旧校注，原文错误另加校注，不静默修正原意。
3. 同步每课头部、源提交、源文件最近修改提交、索引和哈希。区分原始字节与 LF 规范化文本哈希；换行差异不能误报为内容变化。文件改名或删除时追踪迁移，不伪造版本匹配。
4. 校验代码块语言与内容、提示条数和行内命令、章节覆盖、源哈希及译文哈希。校注可增加标题数，结构检查不等于语义证明。
5. 默认维护已有译文，不自动翻译所有新课。维护文件不代表新版完整译文已在聊天交付，后续上课仍遵循前置交付约定。

## 3. 技能变更说明与按需注册

比较前后 `skills/` 的 SKILL.md 及附属资源，区分新增、修改和删除。读取实际文件，说明各项用途、变化、依赖、成本、适合的注册范围。

已有入口指向同一源码时，无需复制或重复注册。改名、删除、触发范围改变或个人适配冲突需单列影响，不自动删除用户入口或覆盖适配。

未获授权的新技能先列候选清单等待选择，期间继续独立文件同步与验证。获选技能沿用唯一源码 `skills/<name>` 与项目入口 `.agents/skills/<name>`；Windows 沿用既有 Junction 模式。已有正确入口复用，同名冲突保留并说明。只改获选项目入口，不上传 OpenViking，不改全局技能、配置或插件。

验证链接类型、目标、入口与源内容哈希，并实测客户端发现。可通过本机 Codex app-server 的 JSON-RPC `initialize` → `initialized` → `skills/list`，传入 `cwds=[仓库根]`、`forceReload=true`，核对名称、路径、`scope=repo` 和启用状态。启动入口从当前安装查找，不硬编码 npm 路径；尊重用户已有禁用设置。客户端不可用时只能报告结构检查，不能声称已验证发现。

## 4. README、验证与本地提交

实时枚举技能源码及实际入口，更新 `skills/README.md` 的分类、数量、用途、示例和维护说明，区分“存在源码”与“已注册”。未选择的新增技能不能计入已注册数量。检查本地链接、围栏语言与闭合、清单覆盖。

修改既有索引即可，不强制生成额外日报或变更日志；逐文件说明可直接在聊天交付。

验证依据实际影响：上游合并按当前 AGENTS 做课程、认证、数量等必要审计；手册变化加对应检查；本地代码和配置变化做针对性运行。仅文档改动不新增镜像文案的测试，通过后不无理由重复全部检查。

区分环境失败与内容失败。Windows 的 `python3` 别名失败可用正确解释器或既有 WSL 复核；端口占用不能擅自终止服务。缺失的验证明确报告命令、原因、影响及待验证项，不标为通过，也不为通过检查而改无关上游内容。

完整维护模式在验证后本地提交本轮已完成的相关变更。仍待技能选择或冲突处理时，先交付可独立完成的部分，说明剩余事项。暂存前复核 HEAD、分支、暂存区归属和快照，按明确路径暂存，不用 `git add -A`。遵循每课提交及本地中文提交格式，可按产物同步和技能文档分别提交，不混入无关改动。用户明确授权推送后，再核对分叉和快进状态执行。

## 交付逐项变更说明

先报告结果，再提供：

- 同步来源、前后版本及实际新增内容分类。
- 本地产物逐文件或同类文件组的“触发变化 → 改了什么”，附可点击路径；文件很多可用紧凑表格，不能只报总数。
- 主要核对无影响的产物，以及保留原状、需重跑或待决定的内容和原因。
- 技能新增／更新、选择状态、注册及实际发现结果。
- 验证、本地提交号、工作区剩余改动及是否推送。

没有变化时直接报告核对范围和结果，不制造文件改动或空提交。
